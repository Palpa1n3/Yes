# What Alton can do

Written automatically by Alton from its own tool definitions (version 1.9.0); don't edit by hand.
80 tools.

- **add_note**: Save a quick note for the user (shown in the Notes tab).
- **add_to_list**: Add items to one of the user's lists (shopping, to-do, packing…). The list is created if needed. Use "To-do" for tasks.
- **alton_roadmap**: Your (Alton's) development plan, from ROADMAP.md in your project: the phases, what's done (✅), part-done (🔶) and still to do (⬜), the phase you're on and the next items; plus improvement ideas the user accepted, and wishes from the Notes "Alton roadmap" list that the plan doesn't cover yet. action "status" (default), "phase" with name (one phase's items), "wishes" (each wish: planned as which item, or not planned). To change ROADMAP.md (tick an item, add a planned item), edit it in dev_sandbox and apply it with the user's approval.
- **analyze_arc_code**: Analyse your own (Alton's) source code as a whole, read-only. action "overview": the areas, biggest files, code with no tests, and TODO/FIXME notes. action "symbol" with name: where a function/class/type/constant is defined and every place it's used (file:line). action "file" with path (e.g. src/main/services/email.ts): its exports and imports, what imports it, everything a change to it would affect, and the tests that cover it. Use before explaining how something works, finding a bug's cause, or planning a change; then read_arc_source for the actual lines.
- **apply_self_change**: Put a change you (Alton) made and checked in your development copy into the real project, with the user's approval. action "apply" with message (a short plain description, e.g. "Update the voice audio to AudioWorklet"): only works when every check ran after your last edit and nothing new failed, the project has no uncommitted work, and it's at the same version the copy started from; the user approves; it's applied, verified file by file and committed (not pushed). action "push": send that commit to GitHub (starts a release build; the user approves again). action "revert": undo the latest Alton self-change with a new commit (approved). Explain the change in plain words before applying.
- **cancel_app_reminder**: Cancel app-triggered reminders matching these words.
- **cancel_timer**: Cancel timers whose label contains the given words, or "all".
- **check_minecraft_mods**: Check modded Minecraft installs (default launcher, CurseForge, Prism, Modrinth, Technic): mod count, duplicate mods (two versions of the same mod), mixed loaders, the latest crash report and recent errors from the log. Use for Minecraft crashes or mod conflicts; explain the cause and which mod to remove or update.
- **close_app**: Politely ask a running app to close (like clicking its X), so it can still ask to save. The user is asked to approve first. Use the app name as the user would say it or as shown in get_system_status topProcesses (e.g. "opera", "spotify").
- **control_arc**: Control ARC's own interface: open a tab (value: overview, chat, notes, system, tasks, apps, network, storage, routines), open settings (value: optional section such as voice or gaming), start a new chat, start a research chat (value: optional topic), turn research mode on/off for this chat, switch to a saved chat (value: its name), export or pin this chat, rename it (value: new name), scan for disk space to free (the user then chooses in the Storage tab), or turn gaming mode on/off.
- **create_routine**: Create (or replace, same name) a routine from the user's description: a named list of steps run in order, triggered by its phrases, a click in the Routines tab, at startup, or on a schedule. Step kinds and targets: launch_app (app name), close_app (app name), set_volume (0-100, mute or unmute), media_control (play_pause, next, previous, stop), open_folder (desktop, documents, downloads, pictures, music, videos), open_url (http(s) address), search_web (query), set_timer (minutes; label = what for), say (words to speak), briefing (no target), wait (seconds), lock_screen (no target). Only use when the user asks for a routine, shortcut phrase or scheduled automation. Tell them what you created.
- **cyberpunk_mods**: The user's Cyberpunk 2077 mods (installed with Vortex) and their updates from Nexus Mods. Actions: dependencies (requirements listed on Nexus that the user's mods need but aren't installed), install_dependencies (install them all; the user approves; Vortex installs them on Premium), recommend (mods to try: Nexus trending, newly updated and new mods plus ones the user tracks, not already installed, ranked by what they mod most; suggest a few with a reason each), install (`name` from the recommendations; the user approves; Vortex installs it), outdated (mods with evidence they don't work on this game version: old RED4ext plugins, broken REDmod scripts, script compile errors, tweaks TweakXL rejects), remove_outdated (remove them all after the user approves; reversible in the Mods tab). diagnose also reads crash reports when the game crashes while playing (where it crashed, mods on the stack, quest and district, TweakXL's rejected changes). fix (fix the last launch's problem: switch off a crashing RED4ext plugin, send its update to Vortex, or deploy REDmod again without broken script mods; the user approves; undo in the Mods tab), load_order (archive clashes — the first archive loaded wins — alternative versions installed together, suggested moves for patches, and whether the last REDmod deploy failed and why), apply_load_order (save the suggested order; the user approves), diagnose (why the game won't start or crashes on launch: reads its RED4ext and redscript logs, names the plugin it stops on and the Vortex mod behind it, and plugins older than the game's patch; explain the fix in plain words), summary (what's installed, what has updates since the last check), check (ask Nexus now; the first check takes about a minute), find (installed mods matching `name`, with installed and latest versions), open (`what`: folder = the mod's files, page = its Nexus page, game = the game folder, vortex = Vortex's mods folder), update (`name` = a mod or "all"; the user approves, then Vortex downloads and installs it on Premium, or its Nexus Files page opens). Alton never unpacks or runs mod files itself.
- **dev_sandbox**: Your (Alton's) development copy: a separate copy of your own project where you can try a change and test it, without touching the real project. action "start" (a fresh copy from the last commit), "read" with path (from/to lines), "edit" with path, find (exact text, once in the file) and replace, "write" with path and content (whole file), "delete" with path, "check" (runs the typecheck, lint and tests there; asks the user first), "diff" (what changed), "discard". Only source, tests and notes can change (not dependencies, build or release setup, or secrets). Use for an accepted improvement idea or a fix the user wants: make the change, check it, fix what fails, then show the user the diff in plain words. Nothing reaches the real project from here.
- **diagnose_alton**: Diagnose yourself (Alton): reads your whole error log, groups repeated errors into distinct problems with counts, when they started and last happened, a likely cause, and whether they've stopped since the last update; adds the start-up health check. Use when the user says Alton isn't working right, asks what's wrong with you, or before proposing a fix. Read-only. Then read_arc_source to find the cause in the code if needed.
- **download_mode**: Download mode: give Steam as much of the connection as possible. Pauses bandwidth-hungry background apps (OneDrive, Dropbox, Google Drive, other game launchers, torrent clients; reopened afterwards), sets Steam to high priority, keeps the PC awake and warns if Steam has a download limit set. It ends by itself when Steam finishes; "then" can shut down or sleep the PC afterwards (the user approves). on false ends it now. Browsers are left alone: suggest closing streams/videos.
- **find_files**: Search file names in the user's Documents, Downloads, Desktop, Pictures, Videos and Music (newest first, up to 15). Use short distinctive words from the file name.
- **forget**: Forget remembered facts matching these words.
- **get_calendar**: The user's upcoming calendar events (from yesterday to two weeks ahead) with local start/end times. Use for questions about their schedule, appointments, meetings or plans. This is read-only on the PC: to add, move or delete an event, tell the user to ask Alton in the phone app (it changes their calendar straight away), or give them a Google Calendar link to add one.
- **get_clipboard_history**: Text the user copied recently (newest first, passwords hidden), optionally only items containing some words. Use for "what did I copy", "paste that link again", etc.
- **get_emails**: The user's newest email inbox messages (sender, subject, date, unread), plus the unread count. Read-only.
- **get_gaming_sessions**: Recent gaming sessions with performance: game, length, average/peak CPU and GPU load and temperatures, memory use. Use for questions about game performance, stutter, overheating or how long they played.
- **get_lists**: The user's lists with what is still to do and what is done.
- **get_notes**: The user's saved notes, newest first.
- **get_now_playing**: What's playing right now in any media app (Spotify, a browser tab, etc.): title, artist, app, playing or paused.
- **get_optimization_tips**: Check the PC for easy speed-ups: startup apps, days since restart, drive space, memory hogs and power plan, with plain-English tips. Use when the PC feels slow or they ask how to optimise it.
- **get_recent_crashes**: Windows' record of recent app crashes and hangs (with the faulting module and error code) and unexpected shutdowns or restarts. Use when the user says a game or app crashed, froze or the PC restarted by itself; explain the likely cause in plain words and suggest fixes (verify game files, update or roll back the graphics driver, disable overlays or recently added mods, check temperatures).
- **get_system_status**: Read live system telemetry: CPU, memory, GPU, temperatures, disks, network, uptime, and (when available) top processes.
- **get_weather**: Current weather and the forecast for the next few hours, today and tomorrow at the user's saved location, in their units. Use for questions about weather, rain, temperature, or whether to take a coat or umbrella.
- **improvement_ideas**: Your (Alton's) ideas for improving yourself, made from your own error log and code: fixes for recurring problems, tests for untested parts, unfinished TODOs, very large files. action "list" (open ideas), "refresh" (look again now), "accept" / "dismiss" / "done" with id. Suggestions only: nothing is changed. Use when the user asks what you'd improve, or whether anything about you needs fixing. Explain each idea simply and let the user pick; a dismissed idea isn't suggested again.
- **journey_time**: How long it takes to get somewhere by car (default), on foot or by bike, from home (or "from"), using OpenStreetMap routes. There is no live traffic, so the answer already allows a margin for driving; say so. With arrive_by (HH:MM) it also gives the time to leave. For the user's calendar events with a location, Alton also gives "leave by" heads-ups by itself.
- **launch_app**: Open an application on the user's computer. Pass the app's name or a phrase from the user's app list (e.g. 'spotify', 'vs code', 'play music'). Call list_apps first if unsure of the name.
- **launch_game**: Start an installed Steam or Epic game by name (through its launcher).
- **list_app_reminders**: App-triggered reminders still waiting.
- **list_apps**: List the apps in the user's app registry with the phrases that open them.
- **list_background_tasks**: Background research jobs and their status.
- **list_installed_games**: Games installed through Steam or the Epic Games Launcher on this PC (names, store, size).
- **list_routines**: List the user's saved routines (named sequences of actions such as "Focus mode") with their steps.
- **list_timers**: List running and ringing timers/reminders with their labels and time left.
- **lock_screen**: Lock the user's computer (Windows lock screen).
- **look_at_all_screens**: See every monitor at once (multi-monitor setups). Use when the user has more than one screen and refers to 'my other screen', 'the left monitor', or look_at_screen didn't show what they mean.
- **look_at_screen**: See what's on the user's screen right now (the app or game they're using, not ARC). Use whenever they refer to something they're looking at: an error, a setting, a page, a game menu, 'this', 'here', 'what should I pick'.
- **look_up**: Look up what you know about a person, place, project, organisation or thing the user has mentioned (from your knowledge graph of their memories): who they are, other names, and how they connect to the user and to other things. Use when the user mentions someone or something by name and the details would help.
- **manage_goal**: The user's long-term goals with progress (shown in the Notes tab and the morning briefing). list them, add one, update progress (0-100) with a short note of what was done, or remove one.
- **media_control**: Press a media key for whatever is playing (Spotify, a browser video, etc.).
- **minecraft_build**: Build something in Minecraft (Java Edition): you design it as setblock / fill / clone commands with RELATIVE coordinates (~x ~y ~z, from where the player stands; build in front of them, e.g. starting at ~2 ~ ~2), and it is saved into their world as a datapack function. Then in game they type /reload and /function alton:<name> (cheats must be allowed). Use correct block ids (minecraft:oak_planks, minecraft:glass_pane[facing=…] etc.); prefer fill for walls/floors, hollow interiors with fill … hollow or air. Plan the size first, keep it buildable (under 20,000 commands). action "list" shows their worlds (most recent first; default world = most recently played). If the game is open, offer to type the two commands for them with Agent Mode.
- **minecraft_mods**: The user's Minecraft mods (Lunar Client profiles and .minecraft, Fabric). Actions: scan (problems: mods for another Minecraft version, missing required mods, the same mod twice, mods that break each other, what the last crash report and the loader blame), check_updates (Modrinth updates for the profile's Minecraft version), fix (fix what's safe after the user approves: duplicates off, missing mods added from Modrinth, wrong-version mods updated or switched off; undo in the Minecraft tab), update_all (the user approves), profiles. `profile` = part of a profile's name; default = the one selected in Lunar.
- **open_folder**: Open one of the user's folders in File Explorer.
- **open_url**: Open a web page in the default browser. Only http(s) addresses.
- **organize_folder**: Tidy the user's Downloads, Desktop or Documents: loose files are moved into folders by type (Pictures, Documents, Installers…). The user sees the plan and approves first; nothing is deleted and it can be undone.
- **pc_lights**: Control the lights inside/on the PC itself (RGB: motherboard, RAM, fans, GPU, keyboard, mouse… whatever OpenRGB sees). Not room lights: those go through the smart home. If the user just says "the lights" and it isn't clear which, ask. action: "on" (back to how they were), "off", "color" with color (a name like purple / warm white, or #rrggbb), "brightness" with brightness 1–100, "effect" with effect (rainbow, breathing, flashing, static, wave, or a mode name), "devices" (list them), "profiles" / "profile" with profile (the user's saved OpenRGB profiles). Optional device: which light ("RAM", "motherboard", "mouse"…); all by default. Needs OpenRGB's SDK server running.
- **phone_messages**: Read the user's phone text messages, or reply to one, through Windows Phone Link (their Android phone linked to this PC). Uses Agent Mode: it opens Phone Link › Messages and reads the screen, or types a reply. "read": reports the newest conversations (optionally only from "who"); the result arrives as Agent Mode's report, so tell the user it is checking. "reply": types "message" in the conversation with "who" and ALWAYS asks the user before pressing Send. Never invent messages. If Phone Link isn't set up, explain: open Phone Link on the PC and "Link to Windows" on the phone (Samsung has it built in), sign in with the same Microsoft account, and allow Messages.
- **play_on_spotify**: Open Spotify searching for a song, artist, album, playlist or mood (e.g. "lofi beats", "Arctic Monkeys"). When asked for recommendations, pick something that fits what they like (memories, what is playing) and explain the pick in one line.
- **post_to_discord**: Post a message to the user's Discord channel (through the webhook they saved in settings). They approve the exact text first.
- **power_pc**: Shut down, restart or sleep this PC, or cancel a planned shutdown/sleep (including one waiting for Steam). The user is asked to approve, and there is always a countdown (default 1 minute) they can cancel. Use minutes for "shut down in 30 minutes".
- **read_arc_logs**: Your own (ARC's) recent error and warning log: crashes, failed actions, network or API errors. Use when the user says something in ARC isn't working, or asks you to debug yourself.
- **read_arc_source**: Read your own (ARC's) source code, read-only, to explain how a feature works, find the cause of a bug or draft a fix for the user to apply. Without path: lists the files. With query: finds files and lines containing it. With path: returns that file (optionally a line range). It reads the copy of your code that ships with the app (or the user's project folder if they chose one in Settings › Advanced, which has their latest edits). You cannot change files; give the user the exact edit instead.
- **read_email**: The text of one email from get_emails (by its uid). Read-only: it is not marked as read.
- **remember**: Remember a fact about the user for all future chats (preferences, people, dates, details they ask you to keep), or the fix for a problem you solved together (category "solutions") so you can reuse it next time. Use when they ask you to remember something, clearly want it kept, or a troubleshooting session ended with a working fix.
- **remind_when_app_opens**: A reminder that pops up the next time the user opens a particular app (e.g. "when I open Steam, remind me to update my drivers"). Windows only.
- **reply_phone_message**: Reply to a phone message from the PC: the phone sends it through that message's own notification. "reply: on my way" answers the last message read out; give "to" (a person or group) for another. The user may be asked to approve first. Say it's on its way; Alton confirms out loud when the phone has sent it.
- **reveal_file**: Show a file (by full path, e.g. from find_files) selected in File Explorer. It does not open or run the file.
- **run_benchmark**: A quick (about 5 s) benchmark of processor, disk and memory speed, compared with the last run; also how much memory Alton uses. Use for "how fast is my PC", "is it slower than before".
- **run_routine**: Run one of the user's saved routines by name. Use when they ask to start a routine or mode by name; call list_routines first if unsure of the exact name.
- **run_self_test**: Run your own (ARC's) automated test suite from the source folder and report what passes or fails. Use when debugging yourself or checking a fix the user applied. Takes up to a few minutes.
- **schedule_agent_task**: Schedule an Agent Mode task to run by itself later, even if the user is away (e.g. "at 4:50 continue Claude Code", "in an hour, check my downloads and restart the one that failed"). When the time comes, Agent Mode starts and uses the mouse and keyboard to do it; it still asks (on the PC and the phone) before anything risky. Use this instead of a reminder whenever the user wants something DONE at a time, not just reminded. Give "at" (24-hour HH:MM, today or the next time it comes round) or "minutes" (up to 24 hours). Write the task as clear step-by-step instructions for yourself, with the app and what to type or click. Cancel with cancel_timer.
- **search_documents**: Search inside the user's own files (Documents, Desktop, Downloads, OneDrive Documents: text, Word, CSV, Markdown and similar; not PDFs) for words or a topic. Returns file paths with a matching snippet. Use for "find my notes about…", "which file had the wifi password…".
- **search_past_chats**: Search the user's earlier saved conversations with you (all chats, not just this one) for words or a topic. Use when they refer to something discussed before ("what was that recipe we talked about?", "remind me what you said about my router") or when earlier context would help. Returns matching excerpts with chat names and dates.
- **search_web**: Search the web in the user's default browser and show them the results page. Use when they ask to look something up online.
- **self_test**: Your (Alton's) automatic regression tests: once a day, while the PC is idle, a fresh copy of your project's last commit is fully checked (typecheck, lint, every test) and compared with the run before, so anything that used to work and now fails is caught and named. action "status" (latest results and the last week), "run" (now; about a minute). Read-only for the real project.
- **set_timer**: Set a timer or reminder. When it ends the user gets a Windows notification with the label.
- **set_volume**: Set the system output volume (0-100) and/or mute or unmute it. Give at least one of level or mute.
- **shop**: Shop online for the user with Agent Mode (eBay, Amazon, Vinted, or another shop they name): search, scroll and compare listings, and depending on "goal": "find" (report the best options with prices incl. postage), "offer" (make an offer up to max_price) or "buy" (buy the best match within max_price). Offers, Buy It Now, checkout and paying ALWAYS need the user's approval (twice for the final payment); card details are never typed. With "seller_questions", it messages sellers to ask those things (allowed without asking per the user's permission setting; anything that commits to a price still asks). Seller replies take time: offer to check back later with schedule_agent_task ("check my eBay/Vinted messages and tell me the replies"). Before calling, make sure you know what they want (item, size, condition, budget); ask if unclear.
- **smart_home**: Control the user's smart home through Samsung SmartThings: lights, plugs, TV, heating, locks, blinds, garage, and scenes. action "list" lists devices; "status" reads one; "on"/"off"; "set_level" (brightness/volume/blind %, value 0–100); "set_temperature" (value °C); "lock"/"unlock"; "open"/"close"; "scene" runs a scene by name (no device = list scenes). Unlocking or opening a door asks the user first. Use the device name as the user says it.
- **start_background_research**: Research a topic on the web in the background while the conversation carries on; the finished write-up is saved in Notes and announced. Use when the user says "look into X and tell me later" or the research would take a while.
- **steam_downloads**: What Steam is downloading or updating right now (with progress), what is waiting, and any planned "shut down when done".
- **summarise_messages**: Summarise the user's phone messages that reached the PC (grouped by person or group chat, newest first, with what needs an answer). Say it in one or two sentences, e.g. "6 messages: Will's asking about tonight, Mum wants a call, 4 in the group chat about Saturday." Offer to reply.
- **undo_organize**: Undo the last folder tidy-up (puts the files back).
- **update_docs**: Your (Alton's) own documentation, written automatically from your code: CODEBASE.md (every area and file, what it does, size, what depends on it, test coverage) and TOOLS.md (everything you can do, from your tool definitions). action "status" (default): which are out of date. action "update": writes fresh ones into your development copy; then check it and apply it with apply_self_change (the user approves).
- **update_list_item**: Tick off ("done"), reopen ("undone") or remove an item from a list, matched by its words.
- **when_steam_updates_finish**: Wait for Steam to finish the games it is downloading/updating now (or one named game), then shut down the PC (default), put it to sleep, or just tell the user. The user approves first; there is a 2-minute warning before shutting down. Cancel with power_pc action "cancel".
